# Acerola — Sponsor Demonstration Script

**Target length:** 6–8 minutes  
**Live product:** https://acerolaorionjr.github.io/acerola-ai/

## Before the meeting
- Use a test account, not a personal account containing private conversations.
- Confirm sign-in and chat work on the device and network being used.
- Test one normal text prompt, one supported attachment, and image/audio generation only if those paths have been verified that day.
- Keep a short screen recording as a backup, clearly labelled with its recording date.
- Never display API keys, service-role credentials, private user records or another person's conversation.
- Have the public repository and sponsorship overview ready.

## 1. Opening — 30 seconds
"Acerola is a personal intelligence system in development. The goal is to bring AI conversation, memory, multimodal input and focused workspaces into one accessible experience. Today I'll show the current product, explain the architecture and be clear about what still needs validation."

## 2. Product experience — 2 minutes
1. Open the live application.
2. Show the main command-centre interface and mobile navigation.
3. Start a fresh conversation with a simple, repeatable prompt.
4. Show the response and explain the intended user workflow.
5. If available and verified, show a workspace such as Research, Create, Code or Analyze.

Suggested prompt: "Explain the difference between renewable and non-renewable energy in a short table, then give one everyday example of each."

Do not claim a response is researched, sourced, verified or generated by a particular model unless the product visibly and reliably demonstrates that.

## 3. Memory and multimodal workflow — 1–2 minutes
- Explain that persistent memory is intended to retain useful user context under the authenticated account.
- Demonstrate memory only with a disposable test fact and confirm the behaviour before the meeting.
- If attachment processing has been tested, attach a harmless sample document or image and ask a question about it.
- Explain the current client limit: up to five attachments per request; individual files are limited to 8 MB.
- Do not upload confidential, medical, financial or identifying documents for a demo.

## 4. Architecture — 1 minute
Explain the flow in plain language:

Browser application → Agent Core → authenticated Supabase gateway → configured AI provider.

The repository documents OpenAI-first routing with Gemini failover. Credentials are intended to remain server-side. Supabase handles authentication and backend functions.

Show the public GitHub repository and README. Do not imply that a source-code feature is production-proven merely because it exists in the repository.

## 5. Honest status — 1 minute
"Some important work remains: repeatable end-to-end reliability testing, independent security review, user validation, payment lifecycle verification and measured operating costs. We are looking for support to complete these milestones responsibly."

Mention any known outage, incomplete feature or test failure rather than hiding it.

## 6. The ask — 1 minute
"We are looking for a sponsor who can support a defined validation phase through capped infrastructure/API credits, technical mentorship, independent testing or a carefully scoped grant. We would agree deliverables, a budget, reporting and a review date before accepting support."

Do not invent a funding amount. Present a budget only after actual provider costs and milestone estimates have been checked.

## Questions to prepare for
- Who owns and maintains the code and accounts?
- What is the current monthly infrastructure and AI cost?
- How many real users are active, and how is that measured?
- What evidence shows people return to use the product?
- What data is collected, where is it stored and how can it be deleted?
- What happens if the primary AI provider fails?
- Which features are live, beta, experimental or planned?
- What exactly will sponsorship pay for?
- How will progress and spending be reported?

If a figure is not known, say so and provide a verified answer later.
